# تخزين المرفقات

> قاعدة البيانات أو مجلد SMB عبر IFileStore ومنظّف الملفات اليتيمة.
> نُقل هذا الملف حرفياً من CLAUDE.md (2026-10-28) ليبقى CLAUDE.md فهرساً قصيراً. المرجع الحاكم للقرارات: docs/adr/.

## Attachment storage: database or SMB folder (2026-10-14, user approved the plan; ships in 1.2.0)
- `Application/Interfaces/IFileStore` (`SaveAsync(area, data)` → key or **null in Database mode**, `OpenRead(key)` → stream) + `FileAreas` (`vacations`/`tasks`/`map-files`); Infrastructure `Files/FileStore` + `FileStorageSettings` (`FileStorage:Mode` = `Database` default | `FileSystem`, `FileStorage:Root` = folder, normally an SMB share the admin mounts with cifs — the app never speaks SMB). Signatures stay in the DB (`UserSignatures`), by decision.
- `VacationAttachment`/`AssignedTaskAttachment`/`MapEntryFile` have `StorageKey` (nullable, unique filtered index; migration `Attachment_Storage_Key`). Key = `<area>/<yyyy>/<MM>/<guid N>` (validated by regex before any path is built; original name only in the DB); files are written to `.tmp` then renamed, never modified. **Write order:** the handler saves the file first, then the row (content row only when the key is null). **Read:** `Application/Common/StoredFiles.OpenAsync(store, key, dbFallback)` — key → disk stream, no key → the `…Contents` table, so rows from before a switch keep working. File DTOs carry a `Stream Content` (was `byte[] Data`); the `GetAttachmentAsync`/`GetByIdAsync` lookups no longer include content (`GetAttachmentDataAsync` / `GetDataAsync` read it).
- **Deletes are not explicit:** DB cascades (task, map entry, field, pending map file cleanup) leave files behind; `FileStoreSweeper` (`IFileStoreSweeper`, called by `TaskReminderWorker`, at most every 6 h, FileSystem mode only) deletes files older than 24 h that no row references, plus stale `.tmp`; files not matching the key shape are never touched.
- Startup (`StartupSettings`) stops with an Arabic message if the mode is invalid or, in FileSystem mode, the folder is missing / not writable; `/health` has a `files` check (`FileStoreHealthCheck`). No tool to move existing DB content to the folder (user decision 2026-10-14: only new files). Server setup (cifs `/etc/fstab`, `RequiresMountsFor`, backups DB first then folder): `docs/DEPLOYMENT.md` «مجلد المرفقات على File Server عبر SMB». New attachment feature = new `FileAreas` entry (+ regex) + `StorageKey` + a query in the sweeper.
