## Work tasks & dashboards (added 2026-09-28)
- **Work tasks** (`WorkTask` + join `UserWorkTask`) = a branch's recurring/fixed duties (e.g. warehouse: in/out/reports). Each belongs to one branch (name unique per branch), assigned to users **of that branch only** (`WorkTaskRules.EnsureAssigneesInBranchAsync`). `GetForUserAsync` filters by the user's *current* branch, so a transferred user's old tasks disappear. New assignees get a `WorkTaskAssigned` notification (RelatedEntityType `WorkTask` → UI `/tasks/:id`). Branch delete is guarded by `HasWorkTasksAsync`.
  - API `api/WorkTasks`: `GetAll?branchId`/`Get`/`Create`/`Update`/`Delete` (JSON body, policies `ViewWorkTasks`/`CreateWorkTask`/`EditWorkTask`/`DeleteWorkTask`); `My` and `View/{id}` (plain `[Authorize]`; View allowed for assignee, same-branch leaders, SuperAdmin).
  - **Each task's real page doesn't exist yet** — cards open UI `tasks/:id` = `TaskPlaceholderPage` ("جاري العمل عليها"). When a task page is built, give it its own route. Supervisor-assigned ad-hoc tasks are a separate future feature — don't overload `WorkTask` for them.
- **EWMS is a general multi-branch organization platform — vacations are ONE feature.** Dashboards show org-wide info only (structure, staff by role, work tasks & coverage, general activity); **vacation numbers/tables do NOT go on dashboards** — they live on the separate leaders' page `/vacations/stats` (`GET api/Dashboard/Vacations?branchId=`, scope by role: BranchManager→branch, Manager→department, OfficeManager→office, SuperAdmin→all or chosen branch). User feedback 2026-09-28. Layout rules from the same feedback: sections stacked full-width (no side-by-side tables), exactly 4 top stat cards per dashboard in a 4→2→1 grid.
- **Dashboards** `api/Dashboard`: `Overview` (SuperAdmin), `Branch/{id?}`, `Department/{id?}`, `Office/{id?}`, `Me`. No id = the caller's own unit; SuperAdmin passes any id; `ViewBranchDashboard` opens the branch and its departments/offices, `ViewDepartmentDashboard` the department and its offices, `ViewOfficeDashboard` the office. The "head" names shown are the users holding that unit's dashboard permission. Scope checks in `Features/Dashboard/DashboardQueries.cs`; aggregate queries in `Infrastructure/.../DashboardService.cs` (returns DTOs directly). General "آخر الإجراءات" is derived from `User.CreatedAt`, `WorkTask.CreatedAt` and `UserWorkTask.AssignedAt`; the vacation page's actions are derived from vacation status + `UpdatedAt` — there is no audit log table.
  - Shared helpers: `VacationRules.MaxPaidVacationDaysPerMonth` and `VacationRules.StatusAr()` (single source for AutoMapper + dashboards).
  - UI: `features/dashboard/` — `DashboardHome` picks the widest dashboard the user's permissions allow, drill-down routes `dashboard/branch|department|office/:id`, shared widgets in `dashboard-widgets.ts` (`StatTile`, `TaskCards`, `CountBars`, `ActivityList`, `TaskDistributionTable`, plus `VacationRows`/`ActionsTable` used only by `features/vacations/vacation-stats-page.ts`); dashboards reload on incoming SignalR notifications. SuperAdmin manages tasks at `/work-tasks`.
