# الدراسات والمكاتب الفنية

> المرحلة 3 من تحليل «الجنوبية» (مشروع `north`). **3.1 (الكيانات والصلاحيات والقواعد وحراسات الحذف) منجزة؛ 3.2 الـ API والتنبيهات والتقرير، و3.3 الواجهة، و3.4 التجربة الحية لم تُبنَ بعد.** القرارات: [ADR-0017](../adr/0017-studies-and-technical-offices.md).

## المفهوم
على المشروع «أمر دراسة» (`StudyOrder`) يربطه اختيارياً بمعاملة الديوان الواردة التي وصل بها. يتفرع عنه عدة **مخرجات** (`StudyDeliverable`): معماري، إنشائي، كهربائي، ميكانيكي، كميات… أنواعها يعرّفها كل فرع بأسمائه (`DeliverableType`، بيانات لا كود). كل مخرج يُسند إلى مكتب ومهندس **من مشاركي المشروع** ويمرّ بمسار ثابت: **إعداد ← مراجعة ← معتمد أو معاد بسبب**. بعد اعتماد كل المخرجات يُسجَّل **إرسال إلى المركزية** (`StudySubmission`، جولات) وقرارها (اعتماد أو ملاحظات) يدوياً: لا ربط إلكتروني معها.

## الكيانات (`Domain/Entities/ProjectStudies.cs`، migration `Studies_Foundation`)
- `DeliverableType`: فرع، اسم فريد داخل الفرع، `DocumentKind` (يصنّف ملفه في الإضبارة)، ترتيب، تفعيل.
- `StudyOrder`: مشروع، معاملة واردة (اختياري)، رقم الأمر الرسمي، عنوان، ملاحظات، **`Mode` (تسلسل/توازٍ يقرره رئيس القسم لكل أمر)**، **`Status`** (قيد الإعداد ← أُرسلت للمركزية ← اعتمدتها/أعادتها بملاحظات؛ أو ملغاة)، موعد اختياري. الرقم الداخلي `STD-{سنة}-{id:D5}` يُحسب. لا يُحذف: يُلغى.
- `StudyDeliverable`: نوع واحد لكل أمر، ترتيب في التسلسل، مكتب ومهندس مسؤول، موعد، **حالة (`DeliverableState`)**، وثيقته في الإضبارة، **الإصدار المرفوع للمراجعة** (يُثبَّت لحظة الرفع)، المراجع وسبب الإعادة، **الإصدار المعتمد** (= المرفوع وقت الاعتماد، لا يتغير).
- `StudySubmission`: جولة (1، 2…) بتاريخ الإرسال والمرسِل وكتاب صادر اختياري، ثم القرار ومسجّله وملاحظات المركزية ووثيقة القرار (اختياري). **جولة واحدة بانتظار القرار** لكل أمر (فهرس مرشَّح `IX_StudySubmissions_OnePending`).
- كل المفاتيح الأجنبية Restrict، ولا حذف متسلسل جديد (اختبار المعمارية يتحقق).

## القواعد (`Application/Features/Studies/StudyRules.cs`، 43 اختباراً)
- **الحد = حدّ رؤية المشروع** (`ProjectRules.Visible`): تحتاج الأدوار مع صلاحيات الدراسات «عرض المشاريع». إحالة أمر لا تفتحه لقسم كامل.
- **الإعداد** للمهندس المسؤول وحده (والمخرج في «الإعداد» أو «معاد»، والأمر مفتوح، والمشروع غير منتهٍ). **التسلسل** يمنع البدء قبل اعتماد ما قبله **فقط عندما اختاره رئيس القسم**؛ بالتوازي لا قيد.
- **المراجعة**: غير من رفع المخرج وغير من رفع ملفه، **حتى مدير النظام**. الإعادة تشترط سبباً، وبعدها يلزم إصدار أحدث قبل إعادة الرفع. المخرج بانتظار المراجعة مجمَّد.
- **إعادة مخرج معتمد لجولة جديدة**: رئيس القسم بسبب مكتوب (والأمر مفتوح).
- **الإرسال**: بعد اعتماد كل المخرجات (واحد على الأقل)، وجولة واحدة معلّقة. **القرار**: اعتماد أو ملاحظات (تشترط نصها)؛ «ملاحظات» ← أعادتها المركزية ← تُفتح جولة جديدة بقرار من صاحب التعديل. الإلغاء ليس أثناء انتظار المركزية ولا بعد اعتمادها.
- **التنبيه لا القرار**: تجاوز موعد المخرج مرشّح تنبيه مرة لكل موعد (`OverdueNotifiedFor`)، ولا يغيّر حالة شيء.
- حذف المخرج أو تغيير نوعه فقط قبل أن يبدأ العمل عليه (بلا ملف ولا مراجعة).

## الصلاحيات (11، أحد عشر سطراً في `AppPermissions`)
`ViewStudies`، `CreateStudyOrder`، `EditStudyOrder` (تعديل وإسناد وإضافة مخرجات وإلغاء وإعادة فتح)، `PrepareStudyDeliverable`، `ReviewStudyDeliverable`، `RecordStudySubmission`، `ViewDeliverableTypes`/`CreateDeliverableType`/`EditDeliverableType`/`DeleteDeliverableType` (حدّها أنواع فرعه)، `ExportStudiesReport`. سياسات «أيّ من»: `AnyStudyView`، `AnyDeliverableTypeView`. أنواع الإشعارات المحجوزة 60–65.

## حراسات الحذف
فرع له أنواع مخرجات (`IProjectService.ExistsForBranchAsync`)، مكتب أُسند إليه مخرج (`ExistsForOfficeAsync` + معالج حذف المكتب)، موظف له أثر في الدراسات (`ExistsForUserAsync`)، ووثيقة هي ملف مخرج أو قرار مركزية لا تُحذف (`DeleteDocumentAsync`).
