# مفكرتي (قوائم المهام الشخصية)

> نُقل هذا الملف حرفياً من CLAUDE.md (2026-10-28) ليبقى CLAUDE.md فهرساً قصيراً. المرجع الحاكم للقرارات: docs/adr/.

## Personal to-do lists — UI name «مفكرتي» (added 2026-10-06; renamed 2026-10-08, user choice)
- `Domain/Entities/ToDoList` (Name*, Description, `UserId` = owner) — the user wrote the entity; the owner is the creator, taken from the current user and never editable. Items were added 2026-10-08 (see below).
- **Boundary (fixed, my own assumption — tell me if you want sharing):** every permission works on **the user's own lists only**; SuperAdmin on all. `ViewToDoLists`, `CreateToDoList`, `EditToDoList`, `DeleteToDoList` (one per operation, in `AppPermissions`); `GetAll` returns the caller's lists (`?ownerId=` is honored for SuperAdmin only). Someone else's list → 403 (rule in `Features/ToDoLists/ToDoListFeature.cs`). A different boundary (e.g. a manager sees a department's lists) = a new permission.
- `Name` is unique **per owner** (unique index `(UserId, Name)` + friendly Arabic message) — two users may use the same name. The FK to `User` is **Cascade** (like notifications): deleting a user deletes their personal lists, so no delete guard in `DeleteUserCommandHandler`.
- API `api/ToDoLists`: `GetAll`, `Get/{id}`, `Create`, `Update/{id}`, `Delete/{id}` (JSON bodies). Code: `IToDoListService`/`ToDoListService`, `ToDoListProfile`, `ToDoListRequestDto`/`ToDoListResponseDto`. Migration `Add_ToDoLists`. Migration `Add_ToDoItems` (2026-10-08, user decision) inserts the four permission rows and **grants them to every existing role** (roles created later get them from the Roles page).
- **Items** `ToDoItem` (Title ≤ 200, `IsDone` + `DoneAt`, `SortOrder`; cascade with its list; ≤ 200 per list), no new permission: every item operation is `EditToDoList` on **my own lists only** (SuperAdmin any), checked in `ToDoItemHandler` (`ToDoItemFeature.cs`). Endpoints: `POST Items/{listId}` `{title}` (added **first** — since 2026-10-13 the add card is the first card, so new items (also bulk and «from task») get a sort order before all others), `PUT Item/{itemId}` `{title?, isDone?}`, `DELETE Item/{itemId}`, `PUT Reorder/{listId}` `{itemIds}` (must be exactly the list's items — else 400), `DELETE ClearDone/{listId}`. **Every item operation returns the whole updated `ToDoListResponseDto`** (items ordered + `ItemsTotal`/`ItemsDone`); `GetAll` returns counts (`itemsTotal/Done/Overdue`, `nextDueDate`) with an empty `Items`, `Get/{id}` includes the items. UI: `/todo-lists` (tabs «قوائمي»/«اليوم» via `?view=today`) and `/todo-lists/:id`, sidebar «مفكرتي».
- **«مفكرتي» features (2026-10-08, migration `ToDo_Smart_Features`; user approved all suggestions except sharing — sharing was explicitly declined, lists stay private):**
  - **Due date + reminders**: `ToDoItem.DueDate` (day only); `ToDoReminders` (called by `TaskReminderWorker` after the task reminders) → `ToDoItemDueSoon`/`ToDoItemOverdue` once per due date to the list owner only (flags `DueSoonNotifiedAt`/`OverdueNotifiedAt` reset when the date changes or a repeating item advances; done items and archived lists are skipped; entity `ToDoList` → UI `/todo-lists/:id`).
  - **Today** `GET Today`: my undone items due ≤ today in my non-archived lists (overdue first), `overdueCount`/`todayCount`; complete from the page.
  - **Note / importance**: `Note` (≤ 1000), `IsImportant`. **Open important items are always shown first** (user decision 2026-10-13, `importantFirst` in UI `todo.models.ts`; the «المهم أولاً» sort option was removed). Drag-reorder works inside each group (an important item can't be dragged among the others or the reverse) and is disabled while a filter, search or the due-date sort is on.
  - **Item color, add card first, pages (2026-10-13, user requests):** `ToDoItem.Color` uses the same six keys as lists (`ToDoRules.Colors`; empty = none). It is chosen in the item dialog or the quick-add card and shown as a side stripe with a light tint. The add card is the **first** card on every page. A list shows **15 items per page** (`TODO_PAGE_SIZE`); drag indexes are converted from the page to the full order.
  - **Bulk add** `POST Items/{listId}/Bulk` `{titles}` (≤ 100 per call, respects the 200 limit); pasting multi-line text into the add box opens the dialog.
  - **Pin / archive / duplicate**: `PUT Pin/{id}`, `PUT Archive/{id}` (`{value}`, EditToDoList; archiving unpins; an **archived list rejects item edits and rename** until restored), `POST Duplicate/{id}` (CreateToDoList; name «X (نسخة)», items un-done, no dates/repeat/links). Lists carry `Color` (green/blue/purple/orange/red/gray) and `Icon` (≤ 8 chars); GetAll orders pinned first.
  - **Link to the task board** `POST Items/{listId}/FromTask` `{taskId}`: needs `ViewTaskBoard` + `AssignedTaskRules.CanView`; creates an item with the task's title/due date and `LinkedTaskId` (FK **SetNull** — deleting the task unlinks); the item DTO's `linkedTask` shows status (or `available=false` if the viewer lost access). UI: «أضف إلى مفكرتي» in the task drawer footer.
  - **Repeating items** (`Repeat` Daily/Weekly/Monthly, needs a due date): marking one done does **not** leave it done — the due date advances (`ToDoRules.NextDue`, monthly clamped to month end, steps until after today) and it stays open (`LastCompletedAt` set). `PUT Item` fields: `title, isDone, note, isImportant, dueDate, clearDueDate (also cancels repeat), repeat (0 = none)`.
