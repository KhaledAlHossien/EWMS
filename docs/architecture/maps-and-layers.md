## Branch map layers (v1.2.0, 2026-10-11, user decisions)
- **Each branch defines its own map layers, with no code per branch.** Typical uses: the administrative branch's plots and staff, the studies branch's projects, the finance branch's data.
  - A **layer** (`MapLayer`) **belongs to a branch and is used by all its departments**. Fields: name unique per branch, `#RRGGBB` color, `AllowMultiple` (several entries per site, or one), `IsActive`, `SortOrder`, `RowVersion`.
  - Its **fields** (`MapLayerField`) cascade with it: label, type (Text/LongText/Number/Date/Select/YesNo), required, Select options as JSON, order, `IsHidden`. Limits: ≤ 40 fields per layer, ≤ 50 options per field.
  - An **entry** (`MapEntry`) is that branch's information about one shared `Site`. It carries `BranchId` (= the layer's branch), `DepartmentId` (the adder's department; null = branch level), `Values` (JSON keyed by field id), creator/updater and `RowVersion`.
  - People on a site are typed values, not system users: there is no user-picker field type (user decision).
- Code:
  - `Domain/Entities/MapLayers.cs`.
  - `Application/Features/MapLayers/`: `MapLayerRules` is the single source for boundaries, value validation (`NormalizeValues`) and DTOs; plus `MapLayerFeature` and `MapEntryFeature`.
  - `IMapLayerService`/`IMapEntryService`, implemented in `Infrastructure/.../MapLayerService.cs`.
  - `API/Controllers/MapLayersController.cs` holds both controllers.
  - Migration `Branch_Map_Layers` creates the tables only. The seeder inserts the 9 permissions and gives them to SuperAdmin only — grant them to other roles from the Roles page.
- **Permissions (one per operation, fixed boundaries):**
  - Layers: `ViewMapLayers`/`CreateMapLayer`/`EditMapLayer`/`DeleteMapLayer`. Boundary = **my branch's layers**; `Viewer.IsOrganizationWide` sees any branch, chosen in the UI. Reads use the any-of policy `AnyMapLayerRead` (layer + entry permissions).
  - Entries: `ViewDepartmentMapEntries` (my department's), `ViewBranchMapEntries` (my branch's), `CreateMapEntry`/`EditMapEntry`/`DeleteMapEntry`.
  - Entry boundary = `MapLayerRules.EntryScopeFor` → `EntryScope`, like `InstallationScope`: organization-wide = all; `ViewBranchMapEntries` = my branch; otherwise my department; no unit = nothing.
  - `AnyMapEntryView` guards `MapEntries/Site/{id}`. `AnySiteView` now includes the entry permissions (whoever records layer data picks sites).
  - A new entry goes to the creator's department if he is in the layer's branch, otherwise to branch level. An organization-wide user or a `ViewBranchMapEntries` holder may pick another department of the layer's branch.
- **Rules:**
  - Values are validated on the server by type: text ≤ 500, long text ≤ 4000, number = decimal, date = `yyyy-MM-dd`, select ∈ options, yes/no. Required fields are enforced; unknown keys are dropped.
  - A one-entry layer rejects a second entry for the same site.
  - An inactive layer disappears from the map and the add forms; its entries stay read-only.
  - A field's type can't change while it has values.
  - **Deleting a field** (`DELETE MapLayers/Field/{id}?purge=`): with no values it is deleted. With values, the UI asks:
    - «إخفاء» (`purge=false`): sets `IsHidden`, values are kept, `PUT Field/{id}/Restore` brings it back.
    - «حذف نهائي» (`purge=true`): the key is removed from every entry, in one transaction.
  - Hidden fields keep their old values when an entry is edited.
  - A layer with entries can't be deleted (disable it instead).
  - Delete guards: site (entries), department (entries), branch (layers), user (layers/entries).
- Endpoints:
  - `api/MapLayers`: `GetAll?branchId&includeInactive`, `Get/{id}`, `Create`, `Update/{id}`, `Delete/{id}`, `FieldUsage/{fieldId}`, `Field/{fieldId}`, `Field/{fieldId}/Restore`. `Update` upserts fields by id in list order; fields not sent are left untouched.
  - `api/MapEntries`: `Site/{siteId}`, `Create`, `Update/{id}`, `Delete/{id}`. `Site/{siteId}` returns the entries I can see, the active layers I can add to, the layers of the shown entries even if inactive (read-only), and `canCreate`.
- **Layer source: manual or system data (2026-10-12, user decision — «the map should read the database, not only manual entry»):**
  - `MapLayer.Source`: empty = manual (fields + entries). Otherwise the key of an **`IMapLayerProvider`**: a feature whose records reference the shared `Site` (`SiteId`) and carry their unit (`BranchId`/`DepartmentId`), read straight from its own tables with no data entry.
  - `SourceFilter` = JSON `{key: [values]}`; a missing key means all values.
  - The source can't change after creation. A system layer has no fields and accepts no entries; `MapEntries/Site` lists manual layers only.
  - Migration `Map_Layer_Sources`.
  - **First provider: `DevicesMapLayerProvider`** (key `devices`, unit «تركيب»). It shows the installations of the branch, with filters by department, device category, catalog device and status. Example layers: «الكاميرات» (category = كاميرا), «المعطّلة».
  - `GET MapLayers/Sources?branchId=` returns the providers and their filter options from the branch's data.
  - **A new feature with a place = one provider class registered in `AddInfrastructureRigstrationServices`.** Rule for future tables: every record that has a place references `SiteId` + `BranchId`/`DepartmentId`.
  - When a branch that used a manual layer gets its own table, a migration copies the layer's entries (field id → column) and switches the layer's source, so nobody re-enters the data.
- **Map (`MapService`, generic):**
  - For each provider, an **automatic layer** with all the branch's data from it, unless the branch defined its own active layers from that provider (then those replace it).
  - Then the branch's active layers in order: manual = sites with entries (kind `entries`, unit «سجل»); system = provider + the layer's filter (kind = provider key).
  - `MapLayerDto.Unit` + `MapSiteDto.Count` are the generic count. `hasMapData` = union of the providers' `BranchesWithDataAsync` + manual entries.
  - The UI (`mergeLayers`, `layerTotals`) treats every layer the same: «title (count unit)», with no special case for devices.
  - The map shows sites and counts only; details follow each feature's permissions.
- UI (`features/map-layers/`):
  - Page `/map-layers` «طبقات الفروع»: in the sidebar section «الخريطة والمواقع», guarded by `MAP_LAYER_ACCESS`, with a branch filter for organization-wide users. The table shows «من بيانات النظام: …» for system layers.
  - The create dialog asks for the **«مصدر النقاط»**: «إدخال يدوي» or «من بيانات النظام: <provider>». Choosing a provider replaces the field builder with its filter checkboxes; the sources are loaded for the chosen branch.
  - `LayerFormDialog` is the field builder: ordering, Select options one per line, the hide/purge choice, and restore under «حقول مخفية». Deleting or restoring a field runs immediately; everything else is saved with «حفظ».
  - `SiteEntriesPanel` «معلومات الفروع» on the site page: entries grouped by layer, `EntryFormDialog` built from the layer's fields, and an «القسم المالك» select for `canChooseUnit`.
  - `branch-map` merges the visible layers (`mergeLayers`): one point per site, filled with its first layer's color, with inner rings for the next two (`MapPoint.colors`).
  - Map layer keys under the summary show/hide layers (kept for the session). The governorate table shows the installations and entries columns when present.
  - Clicking a site needs `DeviceService.siteAccess().canView`, which now includes the entry permissions.
  - Roles page: groups «طبقات الفرع وحقولها» and «سجلات الطبقات على المواقع» in the «الخريطة والمواقع» section. The device catalog's sidebar icon is now `box`.
- **Files field (type 7, 2026-10-12, user decisions):**
  - The layer admin sets, per field: the allowed **format groups**, the **max files** (1–20) and the **max file size** in MB. The size can't exceed the system cap `MapLayers:MaxFileMegabytes` (default 100, `IMapLayerSettings`, read once at startup). Columns: `MapLayerField.MaxFiles`/`MaxFileMegabytes`/`FileKinds` (JSON keys).
  - Groups (`MapFileRules.Kinds`, sent to the UI by `GET MapLayers/FileOptions`): images (JPG/PNG/GIF/WEBP/BMP/TIFF), pdf, office (DOCX/XLSX/PPTX/DOC/XLS/PPT/ODT/ODS/ODP), text (TXT/CSV/JSON/XML), cad (DWG/DXF), maps (KML/KMZ/GeoJSON/GPX/zipped SHP), archives (ZIP/RAR/7Z), media (MP4/MOV/MP3/WAV/M4A).
  - **The type comes from the file content** (`MapFileRules.Detect`: signatures; ZIP family read with `ZipArchive`; text = no NUL byte in the first 64 KB, so Windows-1256 CSV passes). **Always blocked:** executables/scripts/HTML/SVG/macro documents by extension, OOXML with `vbaProject.bin`, and any ZIP containing a blocked file. RAR/7Z contents can't be inspected (an antivirus on the server is advised). Only images and PDF are previewed inline; everything else is a download (`nosniff`).
  - Storage, in the DB like the other attachments: `MapEntryFile` (EntryId null = pending, FieldId, name, type, kind, size, uploader; cascade with the entry **and** the field) + `MapEntryFileContent` (bytes, cascade). Migration `Map_Entry_Files`.
  - Flow: `POST MapEntries/Files?fieldId=` uploads **one file per request**, stored as *pending*. Policy `AnyMapEntryWrite`; `[MapFileUploadLimit]` sets the request limit from the system cap before the form is read, and a bigger request gets a 413 with an Arabic message. The entry's `Values[fieldId]` = the field's **full list of file ids**; `MapEntryFiles.PlanAsync` validates it (pending files must be the user's own for that field, attached ones must belong to that entry; required = at least one file; max files is checked when adding), then `IMapEntryService.Add/UpdateAsync(entry, …, MapEntryFileChanges)` attaches and removes in the same save. File fields are **not** in the `Values` JSON; hidden file fields are left untouched.
  - Other endpoints: `GET MapEntries/File/{id}?download=` (attached file = the entry boundary; pending = the uploader only) and `DELETE MapEntries/File/{id}` (pending, uploader only).
  - `TaskReminderWorker` deletes pending files older than 24 h (`MapEntryFiles.CleanupAsync`).
  - Field usage counts entries with files. Purge deletes the field's files (cascade); hide keeps them. Uploaded files are part of the user-delete guard.
  - UI: in the builder, a files field shows group checkboxes, max files and max MB (≤ cap). `EntryFormDialog` uploads sequentially with progress (`HttpClient` `reportProgress`), supports drag & drop and does a quick extension/size check (`fileProblem`). Closing without saving deletes this dialog's pending uploads. `EntryFiles` (chips + preview modal/download) is shown on the site page.
  - **Nginx `client_max_body_size` must be above the cap** (release conf: 105m; see `docs/DEPLOYMENT.md`).
- Not built yet (phase 3): search/filter by field values, Excel export, an all-branches map.

## Place search in the site form (moved here from the maintenance notes, 2026-10-28)

- **Place search in the site form (2026-10-03, offline):** `public/maps/syria-places.json` (≈540 KB, 8,595 places: cities/towns/villages/hamlets/suburbs/quarters from OpenStreetMap via Overpass, ODbL — keep the attribution line "بيانات الأماكن © مساهمو OpenStreetMap (ODbL)") with `[nameAr, nameEn, type, lat, lng, governorate]` rows. Built by a one-off script (download → trim → assign governorate); rebuild by repeating the Overpass query `node[place~city|town|village|hamlet|suburb|neighbourhood|quarter]` over area ISO3166-1=SY. UI: `core/utils/places.ts` (`PlaceIndex`: Arabic normalization — hamza, ta marbuta, alef maqsura, diacritics, leading «ال» — and ranking exact → prefix → word-prefix → contains, then city before village), `core/services/places.service.ts` (loads the file on first search only), `features/map/place-search.ts` (combobox, keyboard support) used inside `coordinate-picker`: choosing a result focuses the governorate and sets the point; the user then fine-tunes by clicking. Governorate lookup (server `Governorates.Locate` and client `governorateOf`) accepts a point up to 0.05° (~5.5 km) outside a simplified border — coastal cities (Tartus, Latakia, Baniyas, Jableh) fall just outside the polygons; keep the two tolerances equal. Device permissions in the UI (`DeviceService.access`) are now computed from the user's permissions (the old `Devices/MyAccess` loader and `deviceGuard` were removed; their absence had hidden every device button).
