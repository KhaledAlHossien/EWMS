# مكتب التسعير

> المرحلة 5 من تحليل «الجنوبية» (مشروع `north`). **5أ.1 (الكيانات والقواعد) و5أ.2 (API) و5أ.3 (التذكير والتقارير وربط المهام) منجزة؛ 5أ.4 (الواجهة) و5أ.5 (التجربة الحية) ثم الدفعة 5ب (الأسعار المرجعية والمطابقة مع الفواتير) لم تُبنَ بعد.** القرارات: [ADR-0019](../adr/0019-pricing-office.md).

## المفهوم
يصل إلى مكتب التسعير **طلب تسعير** (`PricingRequest`) يسجّله من يملك الصلاحية (مهندس الموقع لأعمال أو مواد خارج العقد مثلاً)، ويربطه اختيارياً بمشروع وعقد ومعاملة الديوان. بنوده كميات ووحدات ومواصفات. يكلّف صاحب «التكليف» موظفاً من المكتب فيسجّل **عروض الموردين** ويطابقها فنياً **بنداً بنداً** ويقارنها، ثم يختار عرضاً لكل بند بسبب مكتوب ويوثّق التوصية. يعتمدها **غير من أوصى بها** (أو يرفضها أو يعيدها لجمع العروض)، ثم تُرسَل النتيجة إلى الجهة المختصة (مهندس الموقع أو مكتب العقود). ويُعدّ مدير المكتب **محضر اتفاق** (`PricingAgreement`) مع متعهد جديد يعتمده غيره.

## الكيانات (`Domain/Entities/PricingOffice.cs`، migration `Pricing_Foundation`)
- `PricingRequest`: فرع، مشروع/عقد/معاملة (اختيارية)، عنوان ووصف، `OutsideContractScope`، موعد، **`Status`** (مسجَّل ← قيد جمع العروض ← موصى به ← معتمد/مرفوض ← أُرسلت النتيجة، أو ملغى)، مقدّمه، **المكلَّف** ومن كلّفه، **التوصية** وموصيها، **القرار** ومعتمده، **الإرسال** (الجهة والتاريخ ومسجّله)، `OverdueNotifiedFor` (تنبيه التأخر مرة لكل موعد). الرقم الداخلي `PRC-{سنة}-{id}` يُحسب.
- `PricingRequestItem`: وصف، مواصفات، كمية (> 0)، وحدة.
- `PricingOffer`: مورد (من `Contractor`)، رقم العرض، تاريخ الاستلام والصلاحية، **عملة واحدة للعرض**، شروط التوريد، وثيقة داعمة (إصدار مثبَّت). **مورد واحد لكل طلب** (فهرس فريد).
- `PricingOfferLine`: سعر الوحدة والوحدة المعروضة، **نتيجة المطابقة** (لم تُقيَّم / مطابق / غير مطابق)، **الاختيار** وسببه. **سطر مختار واحد لكل بند** (`IX_PricingOfferLines_OneSelected`).
- `PricingAgreement` + `PricingAgreementLine`: رقم رسمي فريد داخل الفرع (`IX_PricingAgreements_BranchNumber`)، تاريخ، متعهد، مشروع/عقد/طلب (اختيارية)، مواصفات وطريقة تنفيذ، **عملة المحضر**، بنود بأسعارها، **الحالة** (مسودة ← مرسل ← معتمد أو معاد؛ أو ملغى)، من أعدّه ومن اعتمده.
- كل المفاتيح `Restrict`، والمبالغ `decimal(18,4)` للأسعار و`(18,3)` للكميات، ولا `HasDefaultValue` على bool أو enum.

## القواعد الصرفة (`Application/Features/Pricing/PricingRules.cs`)
- **الحدّ:** فرع الطلب (ونظرة المؤسسة كل الفروع)، ومقدّم الطلب والمكلَّف يريان طلبيهما دائماً (`Visible` قابل للترجمة إلى SQL).
- **المقارنة:** `Compare` يعيد صفاً لكل سعر بند: القابل للمقارنة ما وحدته كوحدة البند، وغيره بسبب «لا تُقارَن بلا تحويل معتمد». «الأرخص» معلومة تُحسب بين القابل للمقارنة **المطابق فنياً** لكل عملة على حدة. `SelectedTotals` جمع بسيط للمختار لكل عملة (لا جمع بين العملات).
- **الاختيار:** `EnsureCanSelect` لا يقبل إلا مطابقاً، بوحدة البند، وعرضه لم تنتهِ صلاحيته، وبسبب مكتوب. السطر المختار لا يُعدَّل قبل إلغاء اختياره.
- **التوصية:** عرض واحد على الأقل وسطر مختار لكل بند ونص التوصية؛ والاعتماد لغير من أوصى (حتى مدير النظام)، والرفض والإعادة بسبب.
- **التكليف والعمل:** المكلَّف نشط من الفرع ويملك `PreparePricingOffers`؛ وتُسجَّل العروض وتُطابَق وتُختار من المكلَّف (أو مدير النظام) والطلب قيد جمع العروض. بنود الطلب تتجمّد بعد أول عرض.
- **المحضر:** الإعداد بـ`PreparePricingAgreement` وحدها، والتعديل لمن أعدّه ما دام مسودة أو معاداً، والإرسال يشترط الرقم الرسمي وبنداً مسعَّراً، والاعتماد لغير من أعدّه (حتى مدير النظام)، والمعتمد لا يُعدَّل.
- **التنبيه لا قرار:** `IsOverdueCandidate`/`NeedsOverdueNotice` (مرة لكل موعد).

## الـ API (5أ.2)
بنية معالج لكل حالة استخدام (`Application/Features/Pricing/`): `PricingContext`، `PricingSupport` (ربط الـ DTO وأعلام الأزرار وصفوف المقارنة بالقواعد نفسها)، `UseCases/` (`PricingRequests.cs`, `PricingOffers.cs`, `PricingWorkflow.cs`, `PricingAgreements.cs`)، و`IPricingService` ← `PricingService.cs`. الأثر في المعاملة نفسها، وrowVersion يرفض التعديل فوق تعديل غيره.

| المسار `api/PricingRequests` | الصلاحية | ما يفعل |
|--------|----------|---------|
| `GET Search` · `Get/{id}` | `AnyPricingRequestView` | قائمة مرقّمة (فرع، مشروع، حالة، «ما سجّلته أو كُلِّفت به»، المتأخر) وتفصيل بالبنود والمقارنة وأعلام الأزرار |
| `POST Create` | `RegisterPricingRequest` | تسجيل طلب وبنوده (مشروع/عقد/معاملة اختيارية؛ بلا مشروع يُسجَّل في فرع المستخدم) |
| `PUT Update/{id}` · `POST Cancel/{id}` | `AnyPricingRequestEdit` (تسجيل أو تكليف) | تعديل الطلب (البنود تتجمّد بعد أول عرض) وإلغاؤه؛ الحدّ الدقيق في `PricingRules` |
| `POST Assign/{id}` | `AssignPricingRequest` | تكليف موظف نشط من الفرع يملك `PreparePricingOffers` (يتحول الطلب إلى «قيد جمع العروض») |
| `POST Offers/{requestId}` · `PUT Offer/{offerId}` | `PreparePricingOffers` (المكلَّف) | عرض مورد بعملة واحدة وأسعار بنوده؛ التعديل يحدّث الأسطر المرسلة ويحذف ما لم يُرسَل (السطر المختار لا يتغير) |
| `POST Select/{lineId}` · `Unselect/{lineId}` | `PreparePricingOffers` (المكلَّف) | اختيار سطر لبند بسبب مكتوب (مطابق فنياً، بوحدة البند، عرضه لم تنتهِ صلاحيته)، أو إلغاؤه |
| `POST Recommend/{id}` | `PreparePricingOffers` (المكلَّف) | توثيق التوصية بعد اختيار كل البنود (يتحول إلى «بانتظار الاعتماد»، ويُنبَّه المعتمِدون) |
| `POST Decide/{id}` | `ApprovePricingRequest` | 1 اعتماد، 2 رفض، 3 إعادة لجمع العروض (الرفض والإعادة بسبب) — غير من أوصى حتى مدير النظام |
| `POST SendResult/{id}` | `SendPricingResult` | إرسال النتيجة المعتمدة أو المرفوضة إلى جهة مسمّاة (يُنبَّه مقدّم الطلب) |
| `api/PricingAgreements`: `Search` · `Get/{id}` | `AnyPricingAgreementView` | محاضر الفرع |
| `Create` · `Update/{id}` · `Submit/{id}` · `Cancel/{id}` | `PreparePricingAgreement` | الإعداد (مدير المكتب وحده) وتعديل المسودة أو المعاد وإرسالها (يلزم الرقم الرسمي وبند مسعَّر) وإلغاؤها |
| `Review/{id}` | `ApprovePricingAgreement` | اعتماد المحضر أو إعادته للتصحيح بسبب — غير من أعدّه حتى مدير النظام |

- **المقارنة في التفصيل:** لكل بند صفوف (مورد، سعر وحدة، وحدة، عملة، إجمالي، مطابقة، «قابل للمقارنة» وسبب عدمه، «الأرخص»، صلاحية العرض، الاختيار) وأعلام `CanSelect`/`CanUnselect`؛ وعملات البند مجموعات منفصلة، و`SelectedTotals` مجموع المختار لكل عملة.
- **الإعادة بعد التوصية:** يعود الطلب إلى جمع العروض وتُمسح التوصية (يبقى الاختيار قائماً للتعديل) فيوصي المكلَّف من جديد.
- **الإشعارات:** `PricingRequestAssigned`, `PricingRecommendationAwaiting`, `PricingRequestDecided`, `PricingResultSent`, `PricingAgreementAwaiting`, `PricingAgreementDecided` (ربط `PricingRequest` أو `PricingAgreement`). تنبيه التأخر (`PricingRequestOverdue`) في 5أ.3.
- **المصفوفة واللقطات:** `permission-matrix.txt` (+20 نقطة)، `contract/permissions.json` (مجموعة `AnyPricingRequestEdit`)، و`contract/openapi.json`.

## التذكير والتقارير وربط المهام (5أ.3)
- **التذكير** (`PricingReminders` في `TaskReminderWorker`، تكراره آمن): طلب لم ينتهِ (مسجَّل أو قيد الجمع أو بانتظار الاعتماد) وتجاوز موعده ← يُنبَّه مقدّمه والمكلَّف به وحاملو `AssignPricingRequest` في فرعه، **مرة لكل موعد** (`OverdueNotifiedFor`؛ تغيير الموعد يسمح بتنبيه جديد). لا تتغير حالة الطلب بالتنبيه (`PricingRequestOverdue`).
- **التقارير** (صلاحية `ExportPricingReport`): `pricing-requests` (الحالة وعدد البنود والعروض والمكلَّف والموعد و«متأخر»، بحدّ رؤية الطلب)، و`pricing-agreements` (المتعهد والمشروع والإجمالي بعملة المحضر والحالة ومن أعدّه ومن اعتمده، بفرع المستخدم؛ تشترط فوقها `ViewPricingAgreements`).
- **ربط المهام:** نوعا ربط «طلب تسعير» (`PRC-…`) و«محضر اتفاق» (`AGR-…`) في `TaskLinkResolver`: الربط والعرض مشروطان برؤية السجل نفسه.
