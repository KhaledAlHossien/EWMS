# ADR-0004: هوية المستخدم وصلاحياته تُقرأ من القاعدة لا من التوكن

- **الحالة:** مُقرّ
- **التاريخ:** 2026-10-10 (إصلاح من مراجعة)
- **صاحب القرار:** صاحب المشروع

## السياق
كان التوكن (JWT، صلاحيته 120 دقيقة) يحمل الدور والفرع والقسم ويقرؤها الخادم منه. مدير نظام أُنزلت رتبته، أو رئيس نُقل، احتفظ بصلاحياته القديمة حتى انتهاء الجلسة.

## القرار
- **معرّف المستخدم وحده يُؤخذ من التوكن.** `ICurrentUserService.GetUserAsync()` يقرأ المستخدم ودوره من القاعدة (مخزّن مؤقتاً داخل الطلب الواحد)، وحساب محذوف أو معطّل يرمي `UnauthorizedAccessException`.
- الصلاحيات تُقرأ من القاعدة بمعرّف المستخدم (`IUserPermissionService`) فتسري تغييرات الدور فوراً.
- التوكنات في جدول `UserTokens`: `OnTokenValidated` يرفض الملغى والمنتهي، فيصير الخروج إلغاءً فعلياً.
- تغيير دور المستخدم أو موضعه أو تعطيله أو تعيين كلمة مرور له **يلغي جلساته** (`RevokeSessionsAsync`).
- «ممنوع» لمستخدم مصادَق يعود 403 لا 401، لأن الواجهة تُخرج المستخدم عند أي 401.

## البدائل
- تقصير عمر التوكن: يخفف المشكلة ولا يحلّها.
- وضع الصلاحيات في التوكن وتجديده: يعقّد التجديد ويبقي نافذة تأخر.

## النتائج
- كلفة قراءة إضافية لكل طلب (مخزّنة داخل الطلب) مقابل سريان فوري.
- الواجهة تعيد جلب الصلاحيات عبر `GET Auth/Permissions` دون إعادة دخول.
- متابعة قادمة: تجديد الجلسة تلقائياً (بند الإصدار القادم) لأن إلغاء الجلسات يجبر على تسجيل الدخول من جديد.
