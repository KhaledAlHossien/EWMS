# ADR-0011: بوابات الجودة وهرم الاختبارات

- **الحالة:** مُقرّ
- **التاريخ:** 2026-10-27
- **صاحب القرار:** صاحب المشروع (خطة «الأساس الهندسي» بتسعة بنود)

## السياق
اتّسع المشروع بسرعة وبمساعدة أدوات توليد، فخشينا «البرمجة بالإيحاء»: كود يعمل في العرض ويكسر بصمت. اختبارات الوحدة ببدائل الخدمات مرّت بينما فشل التطبيق الحقيقي بتعارض تتبع في EF.

## القرار
أربع طبقات يفرضها CI (GitHub Actions) على كل دمج:
1. **بناء Release مع تحويل التحذيرات إلى أخطاء** وتدقيق NuGet، وفحص `has-pending-model-changes` (تغيير نموذج دون هجرة يفشل).
2. **اختبارات وحدة** للقواعد الصرفة والمعالجات ببدائل.
3. **اختبارات تكامل** على SQL Server حقيقي في حاوية (التطبيق الفعلي + الهجرات + البذر + الوسائط + السياسات).
4. **اختبارات معمارية** بالانعكاس: اتجاه الطبقات، متحكمات رقيقة، كل نقطة بصلاحية، كتالوج الصلاحيات، قواعد النموذج، وتحديد الحذف المتسلسل.
- **مصفوفة الصلاحيات** بطبقتين: لقطة مراجَعة `permission-matrix.txt` (النية؛ أي تغيير يظهر في الـ diff) وفحص حي لكل نقطة (التنفيذ).
- **تعريف الإنجاز لميزة:** اختبارات وحدة لقواعدها، واختبار تكامل لمسارها الرئيسي وحدودها، وتشغيل حي بحساب حقيقي، وتحديث الوثائق، وCI أخضر.
- اختبارات الانحدار للوحدات القديمة بحسب المخاطرة (إجازات، صلاحيات، مخزون، لوحة المهام، كلمات السر)، وكل منها مُتحقَّق بقلب القاعدة.

## البدائل
الاعتماد على الاختبار اليدوي: لا يتسع مع حجم الوحدات.

## النتائج
- الدمج أبطأ قليلاً (تكامل ~45 ثانية) مقابل ثقة أعلى. تتطلب اختبارات التكامل Docker.
- دين معلن في قوائم صريحة (متحكمان غير رقيقين، 28 معالجاً متعدد الطلبات) بدل إخفائه.
