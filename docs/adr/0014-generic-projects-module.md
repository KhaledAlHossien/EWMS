# ADR-0014: وحدة مشاريع عامة لكل الفروع، لا تُحذف مشاريعها

- **الحالة:** مُقرّ
- **التاريخ:** 2026-10-27
- **صاحب القرار:** صاحب المشروع (خطة المراحل من تحليل «الجنوبية»)

## السياق
وثيقة «تحليل النظام للجنوبية» تصف دورة حياة المشروع الهندسي (ديوان ← دراسات ← عقود ← إدارة مشروع ← تسليم/كفالة، ومكتب تسعير). النظام متعدد الفروع، والفروع تختلف في وحداتها ونماذجها.

## القرار
- **عامة لكل فرع:** الوحدات والحالات والنماذج **بيانات لا كود لكل فرع**. المشروع لفرع واحد وتتولاه إدارة واحدة (تتغير بالإحالة)، ومرحلته ثابتة (`ProjectStage`) **لا تتحرك بالتاريخ**.
- **لا يُحذف مشروع**: يُلغى بمرحلة (`Cancelled`)، ولا توجد صلاحية حذف.
- **حدود الرؤية ثابتة** (`ProjectRules.Visible`): مشاركاً أو منشئاً، أو قسمي، أو فرعي، أو المؤسسة. **الإحالة إلى قسم آخر لا تفتح المشروع لمستخدميه.** والوثائق والتدقيق والتقرير تتبع رؤية المشروع.
- الوثائق إصدارات لا تُستبدل؛ الرفع المجزّأ القابل للاستئناف لملفات تبلغ عشرات الغيغابايت ([ADR-0009](0009-attachment-storage.md)).
- مراحل: 0 الأساس ← 1 الجدول/التأخير/التمديد (التقارير الميدانية أُسقطت: لمهندسي المواقع برنامج خاص بهم) ← 2 الديوان ← 3 الدراسات ← 4 العقود والتسليم ← 5 مكتب التسعير. **النظام ينبّه ولا يقرر** ([ADR-0008](0008-separation-of-duties.md)).

## البدائل
وحدة مصممة لفرع «الجنوبية» وحده: تقيّد النظام وتكرر العمل لكل فرع.

## النتائج
- كل جديد يتبع نمط: صلاحيات بحدود ثابتة، تدقيق في المعاملة، إشعارات للمخوَّلين، مزوّد خريطة، تقرير.
- التقارير الميدانية اليومية والأسبوعية (المرحلة 1ب) خارج النطاق بقرار 2026-10-28، ولا تُعاد دون طلب ([ADR-0015](0015-rejected-options.md)).
