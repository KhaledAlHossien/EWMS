# ADR-0003: صلاحية واحدة لكل عملية، ومصدر واحد لها

- **الحالة:** مُقرّ
- **التاريخ:** 2026-09-30 (وأُكمل بحصر القراءات 2026-10-03)
- **صاحب القرار:** صاحب المشروع

## السياق
بدأت الصلاحيات مجمّعة (`ManageVacations`، `ManageMaintenanceLookups`، «تعديل» تشمل الحذف) فكانت إما واسعة أكثر من اللازم أو لا تحرس شيئاً فعلياً (`ManageVacations` لم تحرس أي نقطة). وكانت بعض القراءات مفتوحة لكل مسجَّل الدخول.

## القرار
- لكل عملية صلاحية: `ViewXs` / `CreateX` / `EditX` / `DeleteX`، وتشمل القراءات المساعدة (قوائم الاختيار) صلاحيات عرض خاصة بها.
- **مصدر واحد:** `Application/Common/AppPermissions.cs` (الاسم + الوصف العربي). منه يُبذر الجدول وتُسجَّل سياسة بالاسم نفسه وتُمنح كلها لـ`SuperAdmin` عند كل إقلاع.
- النقاط التي تقبل «أيّ من عدة صلاحيات» تستعمل سياسات `AppPermissions.AnyOf` (لا صفوف في القاعدة).
- لا شيء مفتوح لكل مسجَّل: الاستثناء خمس نقاط هوية (`Auth/login`, `Me`, `Permissions`, `logout`, `Password`).
- إعادة تسمية أو حذف صلاحية يحتاج هجرة تنسخ المنح القديمة إلى الجديدة (البذر يضيف فقط).

## البدائل
صلاحيات مجمّعة `Manage*`: مرفوضة (انظر السياق).

## النتائج
- صفحة الأدوار تشرح كل صلاحية بالعربية، ويعرف مدير النظام ما يمنح.
- إضافة ميزة = صف واحد في `AppPermissions` + سياسة على نقطتها.
- يُفرَض آلياً: `ApiContractTests` (كل نقطة لها سياسة معرّفة، والأسماء فريدة PascalCase بوصف عربي، وسياسات «أيّ من» سليمة) ومصفوفة الصلاحيات المراجَعة `permission-matrix.txt` (أي تبديل سياسة يظهر في الـ diff).
